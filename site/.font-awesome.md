# Font Awesome Configuration

Detected by the Font Awesome agent tools. Commit this file so the whole team benefits.

## Integration

- **Method:** Kit embed via Web Awesome `data-fa-kit-code` attribute (SVG+JS)
- **Version:** 7.3.1
- **License:** Pro
- **Kit ID:** `5cd93bd475`
- **CDN URL:** `https://kit.fontawesome.com/5cd93bd475.js` (not loaded directly — kit code is passed to Web Awesome via `data-fa-kit-code` on `<html>`)
- **Families:** classic, duotone, sharp, sharp-duotone

## Defaults

- **Style:** solid
- **Family:** classic

## Import Pattern

Icons are used via Web Awesome's `<wa-icon>` component. Do **not** use `<i class="fa-...">` tags — this project uses Web Awesome components exclusively.

```astro
<!-- Solid (default) -->
<wa-icon name="book-open" library="fas"></wa-icon>

<!-- Regular -->
<wa-icon name="book-open" library="far"></wa-icon>

<!-- Light -->
<wa-icon name="book-open" library="fal"></wa-icon>

<!-- Brands -->
<wa-icon name="github" library="fab"></wa-icon>

<!-- Duotone -->
<wa-icon name="book-open" library="fad"></wa-icon>

<!-- Sharp Solid -->
<wa-icon name="book-open" library="fass"></wa-icon>
```

## Conventions

- Kit code is hardcoded in `src/layouts/Layout.astro` as `data-fa-kit-code` on the `<html>` element.
- Web Awesome reads `data-fa-kit-code` automatically for all `<wa-icon>` Pro icon lookups.
- Icon names use kebab-case (e.g., `book-open`, not `faBookOpen`).
- Library prefix maps to FA style: `fas`=solid, `far`=regular, `fal`=light, `fab`=brands, `fad`=duotone, `fass`=sharp-solid.
